System design · model choice

LLM Selection

Two Claude jobs on the hot path: read the sales note into fixed fields, then pick a rep and write a short handoff. Scoring and capacity stay plain code — no LLM. Same model for both Claude jobs.

Decision drivers

AccuracyRight facts from the note (seats, deadline, competitor…); routing picks a shortlist rep and a usable handoff.
LatencyBuyer + routing on every new prospect; both must fit the ~60s end-to-end route budget.
CostNegligible per-lead spend vs SMB ACV; skip the buyer LLM when the note is empty.
ScopeLLM only for free text. Capacity, scoring, and commit stay code — so a fast small model is enough.

Options compared

Model Role Buyer latency Extraction accuracy Verdict
Claude Haiku 4.5chosen Buyer + routing ~1.2s p50 100% correct Best latency / quality
Claude Sonnet Same tasks (tried) ~2.3s No clear win Slower, no gain
Claude Opus 4.5 Buyer extract (tried) ~2.1s p50 100% — same as Haiku No quality gain
Rules only Extract fallback <1ms Perfect offline Misses messy free text
Decision: On 15 sales notes we graded by hand, Opus matched Haiku (tier 100%, every fact correct, score error ~3) but was ~1.8× slower. Bigger models did not help — Haiku for buyer extract and routing. Capacity, scoring, and commit stay code.
